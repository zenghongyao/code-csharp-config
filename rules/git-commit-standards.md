# Git 提交规范详细说明

本文件是全局 CLAUDE.md 第 4 节的扩展。引用方式：`@~/.claude/rules/git-commit-standards.md`

---

## 1. 格式

```
<type>: <description>

[body]

[footer]
```

- `<type>` 必填，见第 2 节
- `<description>` 必填，简洁中文说明，完整描述本次做了什么及目的（可带补充说明）
- `body` 可选，详细描述，见第 3 节
- `footer` 可选，用于关联 issue 等

**不推荐 scope**：Conventional Commits 标准的 `type(scope):` 写法括号繁琐、scope 取名歧义大，本规范统一去掉，把所有信息合在 description 里。

---

## 2. type 类型与推荐动词

| type | 含义 | 推荐中文动词 |
|------|------|-------------|
| `feat` | 新功能 | 新增 / 引入 / 接入 |
| `fix` | 修复 bug | 修复 / 修正 |
| `docs` | 文档（不含代码改动） | 同步 / 更新 / 补充 / 调整 |
| `style` | 代码格式（不影响运行） | 格式化 / 统一 |
| `refactor` | 重构（不增功能不修 bug） | 重构 / 抽取 / 拆分 |
| `perf` | 性能优化 | 优化 |
| `test` | 测试 | 新增测试 / 补充测试 |
| `chore` | 构建/工具/配置变动 | 调整 / 升级 |
| `deps` | 依赖更新 | 升级 / 更新 |
| `revert` | 撤销提交 | 撤销 |
| `version` | 版本号更新 | 升级到 |
| `merge` | 合并分支 | 合并 |
| `wip` | 工作进行中（临时） | 开始开发 |
| `conflict` | 解决合并冲突 | 解决 |

---

## 3. description 描述

- 不超过 70 字（超 70 字放 body）
- 中文动词开头（对应 type）
- 完整描述"做了什么 + 目的/对象"，**让标题能脱离项目背景读懂**
- 不加句号
- 不出现版本号、AI 关键词（见第 5 节）

---

## 4. body 正文结构

按以下结构组织：
1. **改了什么**：列出主要文件/功能变化
2. **为什么改**：说明动机/原因（可用"之前..."开头）
3. **怎么用**：如有 API 变化，说明调用方式
4. **影响范围**：影响哪些子模块/服务

---

## 5. 不允许出现的内容

### 5.1 版本号 / 方案标识

- ❌ `v9.x`（如 `v9.4`、`v9.5`）
- ❌ `方案A`、`方案B`、`方案C`
- ❌ `补丁`、`patch`
- ❌ `V1.0`、`V2.0`、`版本号`

### 5.2 装饰符号

- ❌ `★`（五角星）
- ❌ `▶◀◆●■` 等装饰符号
- ❌ `✓`、`✗` 等勾叉符号
- ❌ `→←↑↓`（业务说明除外）
- ❌ `=====`、`----` 等分隔符

### 5.3 元信息

- ❌ Git commit hash
- ❌ 完整 branch 名
- ❌ 时间戳
- ❌ 作者姓名
- ❌ 文件路径过长

**允许**：技术性说明（如"C# 7.3 兼容：避免 switch expression"）可作为注释或 commit message 的说明性文字。

### 5.4 AI 痕迹关键词（全局生效）

commit message 应像正常开发者的描述，不应直接提及 AI 协作过程。AI 化的关键词会暴露使用痕迹，降低代码审查可信度。

| 类别 | 禁用词 |
|------|--------|
| AI 工具 | `agents`、`agent`、`Agents`、`Agent`、`claude`、`Claude`、`claude code`、`Claude Code` |
| AI 生成 | `AI 生成`、`AI 协作`、`由 Claude 生成`、`Generated by`、`generated by AI` |
| 协作过程 | `任务`、`任务清单`、`TodoList`、`todo list`、`上下文`、`context`、`prompt`、`指令` |
| 项目记忆 | `项目记忆`、`memory`、`记忆`、`AI 协作记录`、`AI 上下文` |
| 元描述 | `本会话`、`本次会话`、`积累`、`累积` |

## 6. 好示例 ✅

```
feat: 新增 Checksum 超时强推机制，避免设备字段缺失漏推

之前 某设备字段永远不完整导致 Checksum=false 永远漏推
- ProjectConfig 加 MaxPushDelayHours
- BasePushRecordService 加 IsTimeout/ComputeChecksum
- 4 个 PushRecordService 同步改造

影响：数据齐全立即推；超时强推；已推不重复
```

```
feat: 新增 ChecksumTime 字段记录打标时间，方便区分数据齐全 vs 超时强推

之前 无法判断 Checksum=1 是数据齐全立即还是超时强推，加打标时间字段
- 4 张 push 表 CREATE TABLE 加 ChecksumTime DATETIME NULL
- 4 个 PushRecordDto 加 ChecksumTime 属性
- BasePushRecordService 加 ApplyChecksum（反射设时间）
- 4 个 MERGE SQL 加 ChecksumTime（CASE WHEN 仅 0→1 跳变写一次）
```

```
refactor: 抽 IDapperHelper 接口 + DI 注入，解决静态方法难 mock

之前 DapperHelper 静态方法无法 mock，改为接口可注入
- 新增 IDapperHelper 接口
- DapperHelper 实现接口 + 加 ILogger 记录异常
- 4 个 PushRecordService + 8 个其他 Service 构造函数注入
```

## 7. 坏示例 ❌

```
v9.5.1 修订：每个子模块用 IsTransferTypeEnabled 守卫

★ 异常检测服务注册（3 个子模块）

【修订】频率配置外部化，方案A 重构

更新项目记忆：加 ChecksumTime 字段写入机制说明

由 Claude 生成：接入异常检测

agents 协作记录：实现 IDapperHelper

feat(推送): 加超时强推机制  ← 括号写法，本规范不用
```

## 8. 提交前自检清单

- [ ] type 在允许列表内（见第 2 节）
- [ ] description ≤ 70 字
- [ ] description 完整，脱离项目背景也能读懂
- [ ] 不含 `v9.x`、`方案A`、`★` 等
- [ ] 不含 AI 痕迹关键词（见 5.4）
- [ ] 正文有"改了什么 / 为什么 / 影响范围"
- [ ] 不含 git hash、branch 名、日期
- [ ] 不含 `★` 等装饰符号
- [ ] 与上次 commit 风格一致

---

## 9. 适用范围

commit message 标题与正文、PR 描述、code review 评论。所有项目生效。
